# Steam 游戏市场分析与相似游戏推荐

项目代码仓库：[steam-game-analysis](https://github.com/qinmoshang654/steam-game-analysis)。

数据来源：Nik Davis，Steam Store Games (Clean dataset)，Kaggle。
https://www.kaggle.com/datasets/nikdavis/steam-store-games

数据原作者的采集、清洗说明：
https://nik-davis.github.io/posts/2019/steam-data-collection/
https://nik-davis.github.io/posts/2019/steam-data-cleaning/
https://nik-davis.github.io/posts/2019/steamspy-data-cleaning/

这是一份2019年前后的历史快照。价格沿用作者清洗后的英镑未折扣价格；owners为估计区间，不是精确销量。主表的游玩时间零值不当作确定的零游玩时长，主聚类不使用该字段。

## 运行

使用 Python 3.12，实验记录的版本为 Python 3.12.14。在仓库根目录打开终端，先安装依赖：

```text
python -m pip install -r requirements.txt
```

从上方 Kaggle 地址下载数据集，解压后将以下两个原始 CSV 文件放到仓库根目录下的 `data/raw/` 文件夹中，不需要其余数据文件：

```text
data/
└── raw/
    ├── steam.csv
    └── steamspy_tag_data.csv
```

仓库提供源代码、依赖清单和运行说明；原始数据需自行下载，实验结果和模型由程序生成。准备数据后，按以下顺序运行基础实验、结果核验和推荐示例：

```text
python run_analysis.py
python audit_results.py
python recommend.py --appid 413150
python recommend.py --appid 620 --method FullTags
```

默认推荐方法根据验证集 Precision@10 选定。本次为 CoreContent。命令行演示在完整历史目录中排除查询自身；正式评测始终仅使用训练集作为候选目录。

## 实验协议

先以标准化开发商完整字段字符串分组，按60/20/20比例随机划分组（实际游戏数16040/5569/5466），保证同一完整开发商字段不跨集合。多开发商字段不进一步拆解，因此不声称所有参与公司完全互斥。词表、IDF、标准化和模型仅由训练集拟合。

市场聚类使用价格对数、评价数对数、Wilson好评率下界、距2019-05-01的发行天数对数四个特征。比较KMeans、MiniBatchKMeans、GaussianMixture以及K=2/3/4/5/6/8；依据固定2000个验证游戏的轮廓系数选择，且验证全集的最小组占比至少2%。测试评估不重新选模型。另有五随机种子稳定性、固定模型重采样区间和统一四维空间中的单特征消融。

推荐验证从验证/测试游戏各抽500个查询，隐藏一个原本存在的标签。目标标签在训练目录至少出现50次、至多覆盖一半目录，并且不与查询的官方类型/玩法字段直接重合；查询须有至少五个完整标签。类型/玩法/核心三标签/完整371维标签分别构造二值TF-IDF。评测Precision@10、Hit@10、目录覆盖率和去除隐藏标签后的列表内容多样性。标签恢复是内容检索代理任务，没有用户反馈，不等于真实推荐准确率。

完整标签相对仅类型方案的测试P@10差异为0.0214，查询级配对bootstrap区间跨零；验证集选择的CoreContent在测试集也未超过热门基线的P@10。保留这些负面结果，不以测试集最高值替换已选模型。游戏查询级重采样没有处理开发商内部相关性。

运行基础实验后，`results/` 中生成实验协议、清洗数据、划分、验证对比、逐游戏分群、每条推荐及隐藏标签、审计结果和模型，`figures/` 中生成实际实验图。无需预先下载这些输出目录。`refresh_figures.py` 可在基础实验完成后，利用已保存结果重新绘制基础实验的六张图。

## 机制解释与扩展实验

先完成上面的基础实验，再按以下顺序运行扩展分析、扩展结果核验和新增方法的推荐示例：

```text
python deepen_analysis.py
python audit_deep.py
python recommend.py --appid 413150 --method GenrePopularity
python recommend.py --appid 413150 --method BlockTags75
```

扩展程序保留基础实验输出，写入 results/deep/，并生成 figures/07 至 10。主要分析：

- 用评价量浅树解释既有聚类；30次开发商成组重抽样，同时重估标准化与聚类；替换Wilson口径、平滑方式、缩放方式与低评价样本。
- 在同一查询/候选目录上加入类型匹配加热度、仅标签、四种分块权重；分别报告总体P@10、标签宏平均、相对随机水平的逐查询平均提升倍数。
- 按目标标签训练占比、查询评价量和可见标签数量分层；以开发商为单位进行配对重采样。
- 固定候选和隐藏目标，随机删除查询可见标签25%/50%/75%，五个种子重复；输出均值和标准差。
- 按完整标签相对核心内容的得分差，统一选择正反案例；独立复算50,000条测试推荐的相关性，并确认原四方案排名完全重现。

扩展问题是在已查看基础实验测试结果后提出，仍属于探索性分析；相同测试集不是新的确认性留出集。新权重仅按验证集选择，不能因此恢复测试集从未被查看的性质。默认命令保留基础实验选中的CoreContent，新增方法需显式指定。

本次扩展没有证明复杂方法普遍更好：类型匹配加热度总体P@10最高，但完整标签在低频目标、标签宏平均和目录覆盖上更有优势；随机缺失一半标签时核心内容更稳。原始两组主要反映评价积累，删去低评价游戏后结构改变很大。核心三标签与完整导出在1,415款游戏上不是包含关系，按原字段分别保留；删除掩码基于两者并集，不把来源差异误当作性能退化。标签隐藏也可能保留近义标签线索，不等同于真实用户反馈。

推荐命令的score_type区分余弦分数与类型匹配加热度的排序分数，后者不应被解释为0至1的相似度。演示在全历史目录检索，正式评测仅在训练目录检索。
